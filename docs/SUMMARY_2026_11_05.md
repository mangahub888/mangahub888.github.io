## 🌟 ภาพรวมความสำเร็จ (Executive Summary)
ในรอบวันนี้ ได้พัฒนา ติดตั้ง และเปิดใช้งานระบบประมวลผลดึงคำอัตโนมัติด้วย AI (**Manga OCR + EasyOCR**) บน **GitHub Actions** ควบคู่กับการควบคุมผ่าน **Google Apps Script (GAS)** และเชื่อมโยงกับหน้าบ้าน **MangaHub Web App (React + Vite)** สำเร็จสมบูรณ์ 100%:

1. **ระบบ AI Auto OCR Pipeline บน GitHub Actions**:
   - เชื่อมต่อโฟลเดอร์ Google Drive สกัดภาพการ์ตูน ดึงข้อความภาษาจีนด้วย AI แล้วแปลงเป็นไฟล์โปรเจกต์ **MangaToolPlus (`.mtp`)** อัตโนมัติ
   - อัปโหลดไฟล์ `.mtp` กลับเข้าสู่โฟลเดอร์ Google Drive ต้นทางทันที พร้อมแนบลิงก์ `[mtp]` ลงใน `worklink` ของ WorkQueue
2. **ระบบ Auto-Chaining Queue (รันลูกโซ่อัตโนมัติจนหมดคิว)**:
   - ปรับปรุงให้ระบบรันต่อเนื่องเป็นลูกโซ่ (Self-Advancing Pipeline) ทันทีที่ GitHub Actions ประมวลผลเสร็จ 1 ตอน จะส่ง Webhook แจ้ง GAS เพื่อมาร์กเสร็จสิ้น และสั่งยิงตอนถัดไปที่รอคิวอยู่ทันที
   - ประมวลผลสำเร็จไปแล้วมากกว่า 38 ตอนต่อเนื่องโดยอัตโนมัติ
3. **Banner แสดงสถานะแบบ Real-time (`AutoOcrStatusBanner.tsx`)**:
   - เพิ่มแถบ Banner แสดงสถานะการรันสดจาก GitHub Actions API, สถิติงาน (เสร็จแล้ว, กำลังทำ, รอเริ่ม, ข้าม), ปุ่มเปิดดู Log สด และปุ่มสั่งรันด้วยมือ (Manual Trigger)
   - เพิ่มระบบ Auto-Refresh หน้ารายการคิวงานทันทีที่ตรวจพบว่างานรันเสร็จสิ้น
4. **การแยกขั้นตอนในตารางคิวงาน (`QueueView.tsx`)**:
   - เพิ่มคอลัมน์ **`2. ดึงคำออโต้`** แยกจาก **`3. QC ดึงคำ`** ชัดเจน
   - **กฎ Kikkuk**: หากคนในช่อง QC ดึงคำ มีชื่อ `Kikkuk` ดึงเสร็จแล้ว $\rightarrow$ ช่องดึงคำออโต้จะปรับเป็น `skip` อัตโนมัติ
   - **กฎ Pratchaya**: หากผู้แปลเป็นชื่อ `pratchaya` $\rightarrow$ ข้ามทั้งดึงคำออโต้ (`skip`) และ QC ดึงคำ (`skip`) อัตโนมัติ
5. **ระบบคิดเงินค่าจ้าง (Expenses & Financials)**:
   - ยืนยันโครงสร้างการคิดเงิน: เงินค่าจ้างดึงคำ (10 บาท/ตอน) **คิดอยู่ที่ขั้นตอน `3. QC ดึงคำ` (`extractorname` / `extractstatus`) 100%**
   - ขั้นตอน `2. ดึงคำออโต้` ดำเนินการโดยบอท AI อัตโนมัติ จึงไม่มีการคิดเงิน/ไม่มีค่าจ้าง
   - ปรับเปลี่ยนข้อความหัวตารางและรายละเอียดในหน้ารายจ่าย (`ExpensesView.tsx`) และหน้าแรก (`DashboardView.tsx`) ให้แสดงเป็นคำว่า **`"QC ดึงคำ"`** ทั้งหมด

## 🛠️ รายละเอียดการพัฒนาและการแก้ไข (Detailed Implementations)

### 1. ระบบ AI Auto OCR Pipeline (`.github/workflows/gdrive_ocr.yml` & `tools/gdrive_ocr_job.py`)
- **โมเดลและเครื่องมือ**: ใช้ `manga-ocr` (ViT + Transformer) ร่วมกับ `EasyOCR` สำหรับตรวจจับและถอดความตัวอักษรจีนจากรูปภาพต้นฉบับ
- **การแพ็กเกจเป็น `.mtp`**: นำพิกัดกล่องข้อความและตัวอักษรมาแพ็กเกจเป็นไฟล์โปรเจกต์ของ MangaToolPlus เพื่อให้ฝ่ายแปลและคลีนเนอร์นำไปเปิดทำงานต่อได้ทันที
- **Sanitize Filename**: เพิ่มฟังก์ชันกำจัดอักขระพิเศษต้องห้ามของ NTFS/GitHub Actions Artifacts (เช่น `:`, `"`, `<`, `>`, `|`, `*`, `?`) ป้องกัน Error การอัปโหลด
- **Workspace Cleanup**: คำสั่ง `rm -rf` เคลียร์ไฟล์ชั่วคราวและรีเซ็ต Git working tree ทุกครั้งหลังประมวลผลเสร็จสิ้น

### 2. กลไก Auto-Chaining Queue บน GAS (`backend/Code.js`)
- **Webhook แจ้งจบงาน (`COMPLETE_MANGA_OCR`)**:
  - เมื่อ Runner ทำงานเสร็จ จะส่งคำขอมายัง Google Apps Script
  - ฟังก์ชัน `completeMangaOcr` ทำการมาร์กสถานะแถวนั้นเป็น `'เสร็จแล้ว'` และใส่ลิงก์ Drive `[mtp]` ลงในช่อง `worklink`
- **สั่งรันตอนถัดไปทันที (`triggerNextPendingMangaOcr`)**:
  - หลังบันทึกเสร็จ จะค้นหาคิวงานถัดไปที่เข้าเงื่อนไข (`uploadstatus === 'เสร็จแล้ว'`, `extractstatus === 'รอเริ่ม'`, ไม่ใช่ Pratchaya และยังไม่เคยทำ OCR)
  - ทำเครื่องหมายในชีตเป็น `'กำลังทำ'` ทันทีเพื่อป้องกันการยิงซ้ำ
  - เรียก GitHub Actions API ยิง Workflow รันตอนถัดไปทันทีแบบลูกโซ่

### 3. ส่วนติดต่อผู้ใช้ (Frontend UI Components)
- **`AutoOcrStatusBanner.tsx`**:
  - ผูกกับ Hook `useGitHubActionsStatus.ts` เพื่อ Polling สถานะ Workflow จาก GitHub Actions
  - มี Effect ตรวจจับเมื่อ Run เปลี่ยนสถานะจาก `in_progress` เป็น `completed` แล้วสั่ง `onQueueRefresh()` อัตโนมัติ
- **`QueueView.tsx`**:
  - คอลัมน์ `2. ดึงคำออโต้` แสดง Badge สด: `เสร็จแล้ว` (พร้อมปุ่มลิงก์ Drive โหลด `.mtp`), `กำลังทำ` (พร้อมไอคอนหมุน), `รอเริ่ม`, หรือ `skip`
  - คอลัมน์ `3. QC ดึงคำ` แสดง Badge สถานะ และชื่อผู้รับผิดชอบ (Default: `Kikkuk`)
